# Execution and integration capability boundaries

These are distinct layers. Transport health is not agent availability, and a provider's report is not an independently tested execution result.

Priority: Muse-native scheduled wake-up and the queue loop are the mainline. Gadget is retained only as a personal isolated experimental alternative; no pairing-dependent work blocks the resource pool, project scopes, resume or local controls. A bounded native one-off still needs an actual completion receipt; no real-time execution path or recurring schedule is claimed to be active.

The primary connector carries transport and observations. The five-minute fallback is a lifecycle recovery mechanism, not a promise of real-time model wake-up. Native agent schedules are a separate platform mechanism. If automatic real-time execution is required, choose a provider with a supported programmatic execution interface explicitly; the scheduler must not silently replace a requested provider or retry an uncertain task with another model.

The earlier blanket no-interface statement is superseded by the official Gadget evidence. Native macOS support, BLE availability on a remote VM and access to a paired Linux host must not be assumed.

The deferred personal-experiment proposal separates a stable physical Linux/BLE bridge from the headless task execution VM. It requires approval for hardware, phone pairing, SDK token, service installation and a dedicated non-sudo execution account. The stock device exposes that account's shell/file permissions. Adapter cancellation, official send deduplication and SDK offline queuing are not supported/established; application request receipts do not imply exactly-once delivery. Source licensing and token service terms are separate. The [official token terms](https://gadgets.muse.ai/sdk-terms) restrict tokens to personal non-commercial use with the owner's account, at most 50 total devices per token, and describe an unsupported service rather than a developer platform. This adapter is not labeled commercially authorized. AgentFleet remains MIT; upstream SDK source is Apache-2.0. No token was requested and no terms were accepted by AgentFleet.
